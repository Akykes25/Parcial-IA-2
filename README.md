# Parcial 2 — Perception, Graphs and Pathfinding

A Hunter NPC leaves the start zone, hunts and gathers 3 Boids in the hunting ground and reaches the exit, while a pack of wolves patrols, spots it with FOV/LOS, howls to the rest of the pack and chases it with A* over a hand-placed navigation graph. Everything runs on its own: there is no player input.

**Author:** Tobias Rodriguez Saco Bikauskas (individual work)
**Course:** Inteligencia Artificial — Parcial 2

## Quick path

1. Open the project with **Unity 6000.3.22f1**.
2. Open `Assets/Scenes/VariantA.unity` (first scene in Build Settings).
3. Press **Play**. Turn **Gizmos** on in the Game view to see radii, FOV, A* paths and last known positions.

Expected within the first minutes: full cycles Start → 3 gathers → Exit, wolves spotting and howling, the Hunter fleeing to a safe zone, and occasional captures followed by a 5 s respawn.

## Level: Variant A (ring)

Built from the reference image *Mapa variante A* and generated by **Tools → Build Variant A Level** (`Assets/Editor/VariantALevelBuilder.cs` + `Assets/Editor/Levels/`), so it can be rebuilt at any time.

- 52 × 32 m ring of 3 m corridors. Start (west) and Exit (east) are joined by a straight axis that crosses the west ring, the hunting ground and the east ring.
- Two safe zones are dead ends off the axis, outside every patrol route, as the brief asks.
- Graph: 41 nodes at corners, crossings, doorways and room centres (no uniform grid), 48 links, none crossing a wall.
- Six wolves:

| Wolf | Route | Mode |
|---|---|---|
| L1 | West ring | Ping-pong |
| L2 | North ring + north room | Loop |
| L3 | East ring | Ping-pong |
| L4 | South ring + south room | Loop |
| L5 | North ring, NW corner ↔ north room door | Ping-pong |
| L6 | South ring, SE corner ↔ south room door | Ping-pong |

`Assets/Scenes/SampleScene.unity` keeps the earlier Variant C (room dungeon) attempt. It was replaced because its safe-zone doors sat on patrol corners and its columns hid wolves until 2–4 m, so no full cycle completed.

### Teacher rules

| Rule | Status |
|---|---|
| No `visited` list in A* | `gScore` + `cameFrom`, stale heap entries skipped |
| No heuristic method | Open set ordered by accumulated cost only (small map) |
| One graph unless the map is large | One graph; wolves filter out safe-zone nodes |
| Line of sight first, A* only when the target is not visible | `NavigationAgent` steers directly when the route is clear, otherwise A* |
| Pathfinding movement with steering behaviours | `PathFollower`: Seek between nodes, Arrive on the last one |
| No NavMesh, no waypoints-and-grid | NavMesh package removed; nodes placed by topology |
| Singleton for the wolves | `WolfPack` scene singleton with instance events; no static wolf list |
| Optimization | Scheduled sensor scans with NonAlloc buffers, LOS only for candidates in range, A* only on demand, no LINQ or per-frame allocations in runtime code |
| No `Find*`, no god scripts, English code | No `Find*` calls in `Assets/Scripts`; one responsibility per class, largest runtime file 373 lines |

## Design notes

- **Threat-aware routes.** The Hunter remembers where it saw each wolf for a few seconds (`ThreatMemory`). A* skips edges that run *towards* a remembered wolf, while running away from a close one stays allowed. If no such route exists, or it is more than twice as long as the plain one, the plain A* route is used. Flee therefore still picks the safe zone with the shortest A* path, among routes that do not cross the wolf.
- **Movement robustness.** A new path never starts by stepping back to an already-passed node; the follower only turns to the next node when the body clears the corner; an agent stuck on a wall replans from the plain closest node.
